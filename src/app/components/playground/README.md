# playground

フッターの「遊ぶ」行から使える体験系の機能。`layout.tsx` の `<Playground />` が1つだけ置かれていて、
キー入力の受付と各モードの描画を受け持つ。同時に動くモードは1つだけ（`src/lib/playground/mode.ts`）。

| モード | 発動 | 本体 |
|---|---|---|
| ターミナル | `` ` `` キー / フッター | `terminal/Terminal.tsx`（ロジックは `src/lib/terminal/`） |
| 破壊モード | フッター「壊す」/ ターミナルで `rm -rf /` | `destroy/`（ロジックは `src/lib/destroy/`） |
| 停電モード | フッター「停電」（停電中にもう一度押すと解除） | `blackout/`（ロジックは `src/lib/blackout/`） |

主要なタイミングで `window` に `playground:<名前>` の CustomEvent を流す（一覧は `src/lib/playground/events.ts`）。

## 破壊モードの仕組み

本物のページは動かさない。画面内の要素を選んで複製をオーバーレイに置き、本物は
`[data-page-root]` を `opacity: 0` + `inert` にして隠すだけ。壊れるのは複製で、修復が終わったら
複製を捨てて、`[data-page-root]` の `style` と `inert`、フォーカス、スクロール位置を元に戻す。
React の状態やイベントリスナーには触らないので、そもそも壊れない。

## 確認のしかた

### 自動テスト

```bash
bun test
```

対象の選び方・破片の形・修復に入る条件・スナップショットの比較・モードの排他を確かめる。

### 修復後に元通りかどうか（開発サーバーのみ）

`bun run dev` で開いたページで、ブラウザのコンソールから:

```js
await window.__playgroundSelfTest()
// → { trigger: "escape", total: 14, restoreCheck: [], ... }
```

破壊モードを始め、1.5 秒後に Esc で修復し、`heal:done` の中身を返す。
`restoreCheck` が破壊前と違っていた項目の名前で、**空なら完全に元通り**。比べている項目は
スクロール位置・フォーカス・`[data-page-root]` の `style` / `inert`・`html` / `body` の `style`・
フォームの値・DOM（子孫の `style` 属性を除く。motion のアニメーションが書き換え続けるため）。

手で遊んだあとも、修復のたびにコンソールに結果が出る
（`[playground] 修復後のページは破壊前と一致しました`）。

### 手で確かめる流れ

1. お問い合わせフォームに何か入力し、少しスクロールしてから入力欄にフォーカスを置く
2. フッターの「壊す」（またはターミナルで `rm -rf /`）
3. 画面が揺れて崩れ落ちる → 要素をクリックで砕く・ドラッグで投げる
4. 「直す」/ Esc / 10 秒経過 / 全部壊す のどれかで修復が始まり、ログが流れて元の位置に戻る
5. 入力した文字・スクロール位置・フォーカスがそのまま残っていること、結果のトーストが出ることを見る

`prefers-reduced-motion: reduce` のとき（OS の「視差効果を減らす」など）は、揺れと物理演算を省き、
タップした要素がフェードで消えて、修復もフェードで戻る。

## 停電モードの仕組みと確かめ方

全画面のレイヤーを `radial-gradient` で暗くし、照らす位置に穴をあけるだけ。レイヤーは
`pointer-events: none` と `aria-hidden` なので、クリックも読み上げもページにそのまま届く。
ページには何も書き換えない（フォーカスだけ「電気をつける」へ移し、解除したら戻す）。

1. フッターの「停電」→ チカチカしてから暗くなり、クリックした位置が照らされる
2. マウスを動かす / スマホでタッチしてドラッグする / Tab でフォーカスを移す → その位置が照らされる
3. 暗いままリンクやフッターのボタンを押せること（「停電」をもう一度押すと解除）
4. 停電中に「壊す」や `` ` `` を押しても何も起きないこと（同時に動くモードは1つだけ）
5. 「電気をつける」か Esc で解除され、押す前の場所にフォーカスが戻ること

`prefers-reduced-motion: reduce` のときはチカチカを省く。
